Research

I work on ferroelectric thin films and the devices built from them: how polarization switches, how that switching is read out through a tunnel barrier, and how it holds up across a population of devices.

My long-term goal is to carry this device physics upward into computing hardware, towards crossbar arrays, reservoir computing and Ising machines whose behaviour follows from the devices rather than around them.

Ferroelectrics Switching Dynamics Tunnel Junctions Computing Hardware

Research interests

  • 01
    Ferroelectric thin films. Epitaxial and CMOS-compatible HfO2, ZrO2 and HZO, and how growth and electrodes set polarization, switching and retention.
  • 02
    Ferroelectric tunnel junctions. Tunnelling electroresistance and multilevel states, read without destroying the polarization that stores them.
  • 03
    Crossbar arrays and in-memory computing. Neuron and synapse behaviour from a single stack, and what survives once the same devices are put into an array or used as a reservoir.
  • 04
    Stochastic and Ising machines. Switching stochasticity treated as a resource rather than a defect, giving a noise source for hardware optimization solvers.
  • 05
    Measurement infrastructure. Automated characterization with per-device logging, so variability is measured across populations rather than inferred.

Instrumentation and software

Measurement protocols are only as good as the automation that runs them across hundreds of devices unsupervised. Most instrument-control code is on GitHub.

  • Automated multiplexed crossbar measurement platform Addresses every cross-point of memristive crossbar arrays and wire-bonded MIM stacks unsupervised, running the full protocol set per device with batch statistics of device-to-device and cycle-to-cycle variability. Built around a microcontroller-driven switching matrix, with MicroPython on the board and PyVISA driving the instruments from the host. Python PyVISA MicroPython Microcontroller
  • Keysight B1500A control software: Python and C++ GUI Two interfaces to the same parameter analyzer over GPIB: a Python/Tkinter and PyVISA suite, and a native C++ GUI. Both cover DC and pulse I-V, endurance, retention, multilevel programming and the neuromorphic protocol set. b1500-studio b1500-gui-cpp Python C++ PyVISA GPIB
  • Keithley 2450 control: on-instrument scripts and a PyVISA GUI TSP-Lua scripts that run on the SMU itself, for routines where host round-trip latency would distort the timing, and a PyVISA desktop GUI for sweeps, pulsing and logging driven from the host. keithley2450-tsp smu2450-studio TSP-Lua Python PyVISA
